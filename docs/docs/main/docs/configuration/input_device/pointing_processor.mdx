# Pointing Processor

Use `PointingProcessor` to turn sensor movement into mouse reports or arrow key taps. Choose one of the four modes below, then [switch modes](#mode-switching) when a layer or key changes.

## Modes

Choose the mode for the input you want to send to the host:

| Mode   | Host input                             |
| ------ | -------------------------------------- |
| Cursor | Mouse movement.                        |
| Sniper | Mouse movement at reduced sensitivity. |
| Scroll | Vertical wheel and horizontal pan.     |
| Caret  | Arrow key taps.                        |

### Cursor

Maps X/Y deltas directly to mouse cursor movement with optional scaling.

```rust
rmk::input_device::pointing::CursorConfig {
    multiplier_x: 1, // scales X delta. 0 disables X.
    multiplier_y: 1, // scales Y delta. 0 disables Y.
    invert_x: false,
    invert_y: false,
}
```

Each sample produces `output = delta * multiplier`. Set an axis multiplier to `0` to disable that axis.

### Scroll

Maps X to horizontal pan and Y to vertical wheel scrolling.

```rust
rmk::input_device::pointing::ScrollConfig {
    multiplier_x: 1, // scales X delta before divisor
    divisor_x: 8,    // divides X motion. 0 disables X.
    multiplier_y: 1, // scales Y delta before divisor
    divisor_y: 8,    // divides Y motion. 0 disables Y.
    invert_x: false,
    invert_y: false, // when false, sensor +Y → wheel -1 (scroll up)
}
```

Scroll mode keeps motion between samples. It computes `total = remainder + delta * multiplier`, emits `total / divisor`, and keeps the remainder for the next sample. A larger divisor requires more movement for each scroll step:

| Sample | delta | total  | output (total/8) | remainder |
| ------ | ----- | ------ | ---------------- | --------- |
| 1      | 5     | 0+5=5  | 0                | 5         |
| 2      | 5     | 5+5=10 | 1                | 10−1×8=2  |
| 3      | 5     | 2+5=7  | 0                | 7         |

### Sniper

Maps X/Y to cursor at reduced sensitivity for precision aiming.

```rust
rmk::input_device::pointing::SniperConfig {
    multiplier: 1, // scales delta before divisor (same for both axes)
    divisor: 4,    // divides motion. 0 disables both axes.
    invert_x: false,
    invert_y: false,
}
```

Like Scroll mode, Sniper mode keeps fractional movement between samples. Increase `divisor` to reduce cursor sensitivity.

### Caret

Maps X/Y to arrow key taps (up/down/left/right). No mouse report is generated.

```rust
use rmk::types::keycode::HidKeyCode;

rmk::input_device::pointing::CaretConfig {
    disable_x: false,  // disable horizontal caret taps
    disable_y: false,  // disable vertical caret taps
    invert_x: false,
    invert_y: false,
    threshold: 100,    // minimum accumulated motion (|dx|+|dy|) to trigger a tap
    keycode_up: HidKeyCode::Up,
    keycode_down: HidKeyCode::Down,
    keycode_left: HidKeyCode::Left,
    keycode_right: HidKeyCode::Right,
}
```

Caret mode accumulates movement until it exceeds `threshold`, then sends the configured arrow key taps. Increase the threshold to require more movement before each tap.

::: note

Caret mode sends unmodified arrow key taps, even when modifiers such as Shift or Ctrl are held.

:::

## Mode switching

To change modes when a layer or key changes, create a controller that receives those events and publishes `PointingProcessorEvent`.

Add the following module to your project. It selects Cursor on layer 0, Sniper on layer 1, Scroll on layer 2, and Caret on layer 3. Pressing a key bound to `User0` also selects Caret.

The example uses `device_id = 255` with the default pointing processor. If your processor is configured for a specific device ID, use that same ID in these events.

::: note

Reserve a subscriber slot for `ActionEvent` in `keyboard.toml`. Its default subscriber count is zero:

```toml
[event.action]
subs = 1
```

:::

```rust title="src/pointing_processor_controller.rs"
use rmk::event::{ActionEvent, LayerChangeEvent, PointingProcessorEvent, publish_event};
use rmk::input_device::pointing::PointingMode;
use rmk::macros::processor;
use rmk::types::action::Action;
use rmk::types::keycode::HidKeyCode;

#[processor(subscribe = [LayerChangeEvent, ActionEvent])]
pub struct PointingProcessorController;

impl PointingProcessorController {
    pub fn new() -> Self {
        Self
    }

    async fn on_layer_change_event(&mut self, event: LayerChangeEvent) {
        match event.0 {
            0 => {
                publish_event(PointingProcessorEvent {
                    device_id: 255,
                    mode: PointingMode::Cursor(rmk::input_device::pointing::CursorConfig::default()),
                });
            }
            1 => {
                publish_event(PointingProcessorEvent {
                    device_id: 255,
                    mode: PointingMode::Sniper(rmk::input_device::pointing::SniperConfig {
                        multiplier: 1, // scales sensor delta before divisor
                        divisor: 8, // divides motion for precision aiming
                        invert_x: false,
                        invert_y: false,
                    }),
                });
            }
            2 => {
                publish_event(PointingProcessorEvent {
                    device_id: 255,
                    mode: PointingMode::Scroll(rmk::input_device::pointing::ScrollConfig {
                        multiplier_x: 1, // scales X delta before divisor
                        divisor_x: 16, // divides X motion for scrolling precision
                        multiplier_y: 1, // scales Y delta before divisor
                        divisor_y: 16, // divides Y motion for scrolling precision
                        invert_x: false,
                        invert_y: false,
                    }),
                });
            }
            3 => {
                publish_event(PointingProcessorEvent {
                    device_id: 255,
                    mode: PointingMode::Caret(rmk::input_device::pointing::CaretConfig {
                        disable_x: false, // disable horizontal caret taps
                        disable_y: false, // disable vertical caret taps
                        invert_x: false,
                        invert_y: false,
                        threshold: 100, // minimum accumulated motion (|dx|+|dy|) to trigger a tap
                        keycode_up: HidKeyCode::Up,
                        keycode_down: HidKeyCode::Down,
                        keycode_left: HidKeyCode::Left,
                        keycode_right: HidKeyCode::Right,
                    }),
                });
            }

            _ => {}
        }
    }

    async fn on_action_event(&mut self, event: ActionEvent) {
        if event.keyboard_event.pressed && event.action == Action::User(0) {
            publish_event(PointingProcessorEvent {
                device_id: 255,
                mode: PointingMode::Caret(rmk::input_device::pointing::CaretConfig::default()),
            });
        }
    }
}
```

Run the controller on the central, including when the sensor is connected to a peripheral. For a unibody keyboard, run it on the keyboard itself. Choose the setup that matches your project:

```rust title="src/main.rs"
#![no_main]

mod pointing_processor_controller;

use pointing_processor_controller::PointingProcessorController;

#[rmk_keyboard]
mod keyboard {
    #[register_processor]
```

Add the constructor to your existing keyboard module. For a split keyboard, use the central's `#[rmk_central]` module in `src/central.rs` instead. See [running a processor](../../features/processor#run-the-processor).

Declare the module and import the controller in `src/main.rs` or `src/central.rs`:

```rust
mod pointing_processor_controller;

use pointing_processor_controller::PointingProcessorController;
use rmk::run_all;
```

After initializing your keyboard and transport, add the controller to the existing task list. Here, `keyboard` and `transport` are your firmware's existing instances:

```rust
let mut pointing_controller = PointingProcessorController::new();
run_all!(pointing_controller, keyboard, transport).await;
```
